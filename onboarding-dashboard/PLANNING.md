# 온보딩 대시보드 기획 노트

> 출발점: "대시보드에 무엇을 보여줄까"가 아니라 **"온보딩 담당자가 실제로 어디서 시간을 버리는가"**.
> 순서: 업무 흐름 → 불편한 점 → 필요한 기능 → 데이터를 어디서 가져오는가 → 화면.

---

## 1. 온보딩 담당자의 실제 업무 흐름

| 시점 | 하는 일 | 지금 쓰는 도구 |
|---|---|---|
| 합격 확정 | 채용 담당에게 합격자 명단(엑셀)을 받아 내 관리 엑셀에 옮겨 적는다 | 채용 시스템 → 엑셀 |
| 입사 2주 전 | 입사 서류 안내 메일을 보내고, 제출 여부를 사람마다 체크한다 | 메일, 엑셀 |
| 입사 1~2주 전 | IT에 계정·노트북, 총무에 자리·출입증·명함, 현업에 버디·권한 신청을 **부서마다 따로** 요청한다 | 메일, 메신저 |
| 입사 직전 | "다 됐나요?"를 다시 물어보며 빠진 것을 찾는다 | 메신저, 전화 |
| 입사일 | 오리엔테이션, 첫날 안내 | |
| 입사 후 2주 | 4대보험 자격취득 신고, 사번 나오면 인사 시스템 정보 확인 | 인사 시스템 |
| 입사 후 1개월 | 법정 의무교육 이수 확인 (LMS에서 엑셀 내려받아 VLOOKUP) | LMS, 엑셀 |
| 7·30·90일 | 적응 설문을 만들어 보내고, 응답을 엑셀로 모아 정리한다 | 구글 폼, 엑셀 |
| 입사 후 3개월 | 수습 평가를 매니저에게 요청하고 받는다 | 메일 |
| 매월 | 온보딩 현황을 보고한다 | 엑셀, PPT |

## 2. 불편한 점 (시간이 새는 곳)

1. **명단을 계속 옮겨 적는다.** 채용 시스템, 인사 시스템, 내 엑셀에 같은 사람이 따로 있다. 입사일이 바뀌거나 입사를 포기하면 내 엑셀만 늦게 바뀐다.
2. **부서별 요청을 사람 단위로 따로 보낸다.** IT에 "이번 주 입사자 5명 계정 부탁드립니다"를 쓰려고 매번 명단을 다시 만든다.
3. **"됐는지"를 확인하려면 다시 물어봐야 한다.** 준비 상태가 한눈에 안 보여서 입사 전날에 노트북이 없다는 걸 안다.
4. **서류 미제출자를 일일이 찾는다.** 6~7종 서류 × 입사자 수만큼 체크해야 한다.
5. **기한이 있는 일을 놓친다.** 4대보험 신고(다음 달 15일), 법정 의무교육, 수습 평가(3개월)는 놓치면 문제가 된다.
6. **설문은 만들고, 보내고, 모으고, 정리하는 게 다 수작업이다.** 누가 아직 안 했는지 모른다.
7. **데이터가 언제 기준인지 모른다.** LMS 엑셀을 언제 마지막으로 받았는지 기억에 의존한다.

## 3. 그래서 대시보드에 있어야 하는 것

| 불편 | 기능 | 화면 |
|---|---|---|
| 1 명단 옮겨 적기 | **채용 시스템·인사 시스템 엑셀을 그대로 올리면** 새 입사자는 추가, 입사일 변경·입사 포기는 자동 반영. 무엇이 바뀌었는지 목록으로 보여 준다 | 데이터 가져오기 |
| 2 부서별 요청 | **"IT에 요청할 명단"을 한 번에 복사**. 받는 곳별로 한 통의 요청 문구를 만들어 준다 | 오늘 할 일, 입사 준비 현황판 |
| 3 준비 확인 | **입사자 × 준비 항목 현황판**. 엑셀 체크리스트처럼 생겼고, 칸을 눌러 완료 표시 | 입사 준비 현황판 |
| 4 서류 수합 | 서류도 현황판의 한 묶음. 미제출자에게 보낼 안내 문구를 바로 복사 | 입사 준비 현황판 |
| 5 기한 있는 일 | 4대보험 신고, 의무교육, 수습 평가를 **법정·규정 기한으로 자동 계산**해서 다가오면 띄운다 | 오늘 할 일 |
| 6 설문 | **설문을 여기서 만들고**, 보낼 대상(입사 7·30·90일 차)을 자동으로 골라 주고, 응답이 모이고, 결과가 바로 나온다. 구글 폼으로 받은 응답 파일도 올릴 수 있다 | 설문 |
| 7 기준일 | 가져온 데이터마다 **마지막으로 가져온 날**을 표시하고, 오래되면 경고 | 오늘 할 일 위쪽 |

**넣지 않은 것**: 예쁜 차트, 실시간 지표처럼 보이지만 출처가 없는 숫자. 담당자의 행동으로 이어지지 않는 숫자는 빼고, 지표는 "누구에게 연락할지"로 이어지게 만든다.

## 4. 데이터를 어디서, 어떻게 가져오나

원칙: **담당자가 이미 받고 있거나, 버튼 한 번으로 내려받을 수 있는 파일**만 쓴다. 시스템 연동(API)은 처음부터 하지 않는다.

| 데이터 | 원천 | 누가 갖고 있나 | 형태 | 주기 | 대시보드에서 |
|---|---|---|---|---|---|
| 입사 예정자 명단 (이름, 이메일, 입사일, 부서, 직무, 직급, 근무지, 매니저, 상태) | 채용 시스템(ATS)의 합격자 목록 | 채용 담당 | 엑셀 내려받기 | 주 1회, 변동 있을 때 | **이메일로 같은 사람인지 판단** → 추가, 입사일 변경, 입사 포기 반영 |
| 사번, 직급, 재직 상태, 퇴사일 | 인사 시스템(HRIS) 인사 기본 정보 | 인사 담당 (본인) | 엑셀 내려받기 | 주 1회 | **이름 + 입사일로 매칭**해서 사번을 붙이고, 퇴사자는 남은 일을 종료 |
| 교육 이수 | LMS 이수 현황 | 교육 담당 | 엑셀 내려받기 | 주 1회 | **사번 + 과정 코드**로 의무교육 항목을 자동 완료 |
| 설문 응답 | ① 대시보드에서 만든 설문 링크 ② 구글 폼·MS Forms 응답 파일 | 본인 | 자동 저장 / 엑셀 내려받기 | 수시 | ①은 바로 반영 ②는 **이메일로 매칭** |
| 준비 항목 완료 (계정, 노트북, 자리, 출입증, 서류) | 각 부서 담당자의 회신 | IT, 총무, 현업, 입사자 | 메일 회신 | 수시 | 현황판에서 칸을 눌러 표시 (자동 메일 버튼은 구글 시트 버전에서) |

> 매칭 키를 무엇으로 할지가 가장 중요하다. 입사 전에는 사번이 없으므로 **이메일**(채용 시스템에 반드시 있음)로 잡고, 사번이 나오면 **사번**으로 넘어간다.

## 5. 화면 구성

| 메뉴 | 담당자가 이 화면에서 하는 일 |
|---|---|
| 오늘 할 일 | 데이터 기준일 확인 → 연락할 곳별로 요청 문구 복사 → 이번 주 입사자 준비 확인 → 기한 있는 일, 설문 확인 |
| 입사 준비 현황판 | 입사자 × 항목 체크, 항목별 미완료 명단 복사 |
| 입사자 | 한 사람의 전체 상황 (준비, 교육, 설문, 수습) |
| 설문 | 만들기 → 보낼 대상 확인 → 발송 → 결과 |
| 데이터 가져오기 | 엑셀 올리기 → 열 맞추기 → 바뀌는 내용 미리 보기 → 반영 |
| 체크리스트 설정 | 준비 항목과 기한 관리 |

## 6. 이 데모의 한계 (솔직하게)

- 데이터는 방문자 브라우저에만 저장된다. 실제 운영은 구글 시트 버전처럼 공유 저장소가 필요하다.
- "설문 발송"은 개인별 응답 링크와 안내 문구를 만들어 준다. 메일 자체는 회사 메일로 보낸다. 같은 브라우저에서 링크를 열면 응답 화면을 체험할 수 있다.
- 각 가져오기 화면에서 **샘플 엑셀**을 받아 바로 올려 볼 수 있다. 샘플은 화면 속 더미 데이터와 맞물리게 만들어져 있어서, 올리면 실제로 입사일 변경·입사 포기·사번 부여·교육 이수가 반영된다.
